# 作りのノート

`README.md` から分けた、実装の解説。動かすだけなら読まなくてよい。

前半は何本ものシーンで繰り返し使っている作り方、後半は全シーンが共有している
仕組み（効果音・色・画面サイズ・PWA）です。シーンを書くときに毎回使う定型と
コード片は [`.claude/skills/new-scene/references/recipes.md`](../.claude/skills/new-scene/references/recipes.md)、
Claude Code 向けの作業ルールは [`CLAUDE.md`](../CLAUDE.md) にあります。

## 位相ひとつで装置を回す

Marble Machine・Cascade Tower・Loom・Domino Ring のような仕掛けものは、
物理演算をまったく使っていません。1 周を 0..1 の位相に割り当て、区間の切れ目を
定数で置き、玉の位置も、板の傾きも、輪の回転も、すべて同じ位相から作ります。

```ts
/** 区間の切れ目（玉の位相）。受け渡し / 滑り台 / シーソー / 落下 / 螺旋 / 下段 / 昇降機。 */
const P_RAIL = 0.03;
const P_SEESAW = 0.18;
const P_DROP = 0.3;
```

玉と仕掛けが同じ 1 つの数から出ているので、**両者は永久にずれません**。
衝突判定も、積分による誤差の蓄積もありません。玉を N 個走らせるときは位相を
1/N ずつずらすだけで、仕掛けの側は「直前に玉が来てからの 0..1」しか見なくて
済みます（`since()`）。装置を増やしても、増えるのは区間の定数だけです。

代償は「当たったから動いた」という因果が勝手には出ないことです。素直に書くと
玉が触れる前に板が動き出して嘘に見えるので、当たる瞬間の前後に待ちを挟んで
います（Cascade Tower の `K_HOLD` は、珠が桶に乗ってから桶が傾き出すまでの間）。

## ループの閉じ方

作り方は 2 つあり、どちらかにはっきり寄せています。中途半端に「ほぼ整数比」に
すると、数分眺めたときにだけ絵が揃って、そこが継ぎ目として見えます。

- **閉じる。** すべての周期を 1 つの数の整数倍に揃える。Cloud Ridge は雲の帯が
  流れきる 48 秒に渦も揺れも色のゆらぎも合わせてあり、一巡すると絵がぴたりと
  重なります。Liquid Orb は 18 秒、Rubik's Cube は後半 6 手を前半の逆手にして
  16.8 秒でステッカーの並びまで元へ戻ります。
- **閉じない。** 周期を整数比にしない。Night Parade の人魂、Solar System の公転、
  Jelly Globe の遊泳、Lava Lamp の塊はこちらで、同じ配置が戻ってきません。

どちらを選んでも、**何も起きていないフレームは作らない**ようにしています。
個体ごとに位相をずらせば画面のどこかでは常に何かが起きますし、D10 Toss のように
一巡のあるシーンでは、ダイスが沈みきる時刻と次の一投が始まる時刻を突き合わせて
あります。

## 動きの時間の決め方

数を決めるときに毎回効いているのは次の 3 つです（静止画としての見え方の
チェックは recipes.md の「見え方のセルフチェック」が正本）。

- **見せ場は長く、終わり方はゆっくり。** 自分が「ちょうどいい」と思う長さは
  たいてい短すぎて、消える・現れるといった変化を詰めると安っぽく見えます。
  Liquid Orb はうねりを 4.7 秒そのまま保ってから、6.5 秒かけて 0 へ落とします。
- **読めない動きを残す。** 対称に並んだものや等間隔の反復は数秒で先が読めます。
  D10 Toss と Dice Field は、跳ね返る場所・止まる向き・次に倒れる方向を乱数で
  決めています。ただし `Math.random()` は使わず、種を「何投目か」「何手目か」から
  作るので、タブを離れて戻っても同じ投げが再現されます。
- **固定シードの偏りは目で見て確かめる。** 少数の乱数は平気で片側へ寄り、それが
  絵の左右の偏りとして出ます。数を散らしたら、種を変えて撮り直して見比べます。

## 数を出す

まず `InstancedMesh` で、ドローコール 1 回に畳みます（書き方は recipes.md）。
珠のれん 32 本 × 22 個、小魚 300 匹、ダイスの盤面あたりまではこれで足ります。

CPU で毎フレーム行列を書き戻せなくなったら、形そのものを GPU へ渡します。

- **Campfire の火の粉 2200 粒。** 頂点シェーダの中で 1 粒ずつの軌跡を時刻から
  組み立てるので、CPU が毎フレーム触るのは時刻・揺らぎ・色の LUT だけです。点の大きさは
  `gl_PointSize` に画素数で入るため、カメラからの距離で割り、`devicePixelRatio` を
  掛けないと高解像度の画面で粒が半分の大きさになります。
- **Night Parade のシーツおばけ。** 釣鐘の形を頂点シェーダが毎フレーム組み立て、
  個体差（拍・歩幅・腕の張り・裾の山の数・種）はインスタンス属性で渡します。
  CPU 側には形が戻ってこないので、当たり判定の類は一切できません。

## 組み込みのマテリアルに差し込む

three の照明とブルームをそのまま使いたいので、`ShaderMaterial` を書き下ろさず、
`MeshStandardMaterial` に `onBeforeCompile` でチャンクを差し込む形を取っています
（Koi Pond の水面、Campfire の炎、Cloud Ridge の雲、Night Parade のシーツ）。
踏んだ落とし穴は 3 つです。

- **`customProgramCacheKey` を必ず付ける。** three はコンパイル済みプログラムを
  マテリアルのパラメータで引いたキャッシュから取り出しますが、そのキーに
  `onBeforeCompile` の中身は入りません。パラメータの同じマテリアルが他にあると
  そちらのプログラムが使い回され、差し込みが無かったことになります。
- **頂点を動かしたら法線を作り直す。** Night Parade は形を返す関数を 3 回呼び、
  角度方向と高さ方向へずらした点との外積から法線を組み直しています。これを
  省くと、襞や肩の張りのところで陰影が裏返ります。
- **色は `ember()` を LUT に焼いて渡す。** Campfire は 24 段の `vec3` 配列を
  uniform で渡し、シェーダ側は 0..1 で引くだけにしてあります。GLSL の中で色を
  組み立てると、そこだけ暖色帯から外れます。

## メッシュを持たない

面の数で形を作るのをやめると、分割数に縛られない細部が出ます。

**Lava Lamp の蝋**にはメッシュがありません。ガラス筒の内側を包む円筒を 1 つ置き、
その画素からレイを飛ばして距離関数（SDF）を追いかけています。塊・首・底の溜まりを
滑らかな合成（smooth union）で 1 つの面にまとめているので、つなぎ目という概念が
なく、首は細らせればひとりでにちぎれ、近づいた塊は勝手に融け合います。面が
見つかった画素は `gl_FragDepth` に本当の深さを書くので、台座や笠との前後も
狂いません。代償は 1 画素あたり 72 回のループで、画面を大きく覆わせられません。

**Koi Pond の水面**も同じ考え方で、形を CPU で作らず「ある点の高さと傾きを返す
1 つの式」をシェーダへ差し込んでいます（次節）。

## 水面の作り

Koi Pond の水面の式は、

- 水面 … 頂点をその高さへ持ち上げ、**画素ごとに**傾きから法線を作る
- 水底 … その式の 2 階微分から集光模様を描く
- 浮き葉 … 葉の頂点をその高さに乗せる

の 3 つが共有するので、波・波紋・集光・葉の揺れは決してずれません。法線を頂点では
なく画素で作っているため、細かいさざ波は板の分割数に縛られずに残ります。

式そのものは正弦波を 8 本足しただけですが、速さは指定していません。深い水の波は
波長が長いほど速く進む（ω=√(gk)）ので、波長から角速度を計算しています。大きな
うねりはゆっくり、細かい波は速く走るというだけで、水面の動きは一気に水らしく
なります。

見た目は 3 つでできています。

| 要素 | 中身 |
| --- | --- |
| 屈折 | ガラスと同じ透過（`transmission`）材で、屈折率は水の 1.333。鯉が水越しにゆがむ |
| 映り込み | 岸の灯り 3 つと暖色の勾配だけの「夜空」を式で書き、フレネルの強さで足す。さざ波が向きを変えるたびに灯りが砕けて粒になる |
| 集光 | 屈折した光が底へ届くまでの面積の変わりぶん（ヤコビアン）の逆数。潰れて 0 に近づくところだけが細い筋になって光る |

鯉は体を直接動かすのではなく、**頭がたどってきた道を体長ぶんさかのぼって**背骨に
しています。時間で等分すると速さのむらで体が伸び縮みするので、距離を積みながら
拾い直しています。胴の断面は途中から横幅を潰しつつ高さを広げるだけで、そのまま
尾びれに化けるので、体と尾のつなぎ目が割れません。

なお `transmission` を使えるのは、その向こう側が不透明なときだけです。three は
透過パスに不透明なものしか描かないので、Jelly Globe のように中身が半透明な場合、
ガラスを `transmission` にすると水槽越しに何も映らなくなります。あちらのガラスは
灯りを拾って弧を返すだけの薄い殻（`clearcoat` + 低い `opacity`）にしてあります。

## 効果音

各シーンには、その動きに合わせた効果音が付いています。右下のボタンか `S` キーで
ON / OFF でき、選んだ状態は `localStorage` に残ります。ブラウザは操作なしに音を
出せないので、ON で終了した場合も次に開いたときの最初のクリック／キー入力まで
待ってから鳴り始めます。

音声ファイルは持たず、`src/audio.ts` が Web Audio API の発振器とノイズだけで
組み立てています。用意しているのは 4 種類だけです。

| 音 | 中身 | 使いどころ |
| --- | --- | --- |
| `pluck()` | 正弦波 + 薄い倍音を指数減衰 | 珠・ドミノ・ダイス・織り機が当たる音 |
| `drop()` | 音程を滑らせた短い正弦波 | 雨だれ、泡が水面へ抜ける音、蝋がちぎれる音 |
| `air()` | 帯域を絞ったノイズ | 風、衣ずれ、雲が稜線をまたぐ音、渦が締まる水の擦れ |
| `drone()` | わずかに離調した 2 本の持続音 | 焚き火・水底・太陽の低い響き |

入眠前に聴く前提なので、音程はペンタトニック（`tone()`）だけを使ってどう重なっても
濁らないようにし、出力全体を 2.4kHz のローパスと長い残響に通して「遠くで鳴っている」
状態に寄せています。音量も低めに固定しています。

鳴らすタイミングは、映像と同じ時刻 `t` から逆算しています。たとえばドミノなら
「`t / CYCLE - u` が整数をまたいだ瞬間 = その牌が倒れ始めた瞬間」です。この
「またいだ回数」を数えるのが `ticker()` で、音が OFF の間 `sound()` は呼ばれないため、
再開時にまとめて鳴らないよう最大 2 回で頭打ちにしています。

シーンが密なもの（ドミノ 84 枚、珠のれん 32 本など）は数本おきにしか鳴らしていません。
全部鳴らすと音が団子になり、眠るどころではなくなるためです。同時発音数も 24 で
打ち切っていて、溢れた音は鳴らさずに捨てます。

## 色づくり

入眠前に眺める前提なので、青い光をほぼ使っていません。色は `src/palette.ts` の
`ember()` に集約してあり、色相は「くすんだ薔薇 → 赤 → 琥珀」の帯だけを使い、
明るいところほど彩度を落として白熱電球のような色に寄せています。シーン側は
0〜1 の値を渡すだけなので、パレットを差し替えれば全シーンの色味が一度に変わります。

同じ帯の中だけでゆっくり色を流すために `drift(t)` があります。数十秒かけて色相を
±0.03 ほど往復するだけで一周はしないので、帯からはみ出しません。

トーンマッピングの露出は 0.92、ブルームは強さを落として半径を広げ（0.42 / 0.85 / 0.28）、
輪郭がじわりとにじむ程度に留めています。光源もろうそくに近い色温度で揃え、
UI の文字色やタブも同じ暖色にしてあります。

明度を上げるときは、ブルームの閾値 0.28 が実質的な上限になります。ここを越えた
面はにじんで白く飛び、色が抜けます。光らせたいのは主役だけなので、Rubik's Cube の
ステッカーのように広い面積を占めるものは、閾値に触れない範囲で濃淡を割り振って
います。

### 映り込む部屋

`stage.ts` は起動時に 1 度だけ「ろうそくが 3 本灯った暗い部屋」を組み、PMREM で
ぼかして `scene.environment` に入れています（強さ 0.3）。環境マップが無いと、
金属やガラスは「暗い面に白い点が 1 つ」になりがちです。three.js の `RoomEnvironment`
は白い蛍光灯の部屋で映り込みが青白くなるので、光源の色は暖色帯の中だけで作っています。

映り込みを弱めたい・消したいシーンは `SceneModule.environment` に倍率を書きます
（0 で無し）。`material.envMap` を自前で持つ材質（Dice Field のガラスなど）は
そちらが優先されるので、この設定の影響を受けません。

### 暗部の縞（バンディング）

背景がほぼ黒で、霧とビネットとブルームのにじみが重なるので、暗いところのなだらかな
階調が 8bit の画面に丸められたときに同心円状の縞になります。途中のレンダーターゲットは
EffectComposer の既定で HalfFloat なので、段が付くのは最後の書き出しだけです。

そこで OutputPass の後ろに、±1/255 の三角分布のディザを掛けるパスを 1 枚置いています
（`stage.ts` の `DitherShader`）。量は 8bit の 1 段ぶんなのでノイズそのものは見えず、
模様は画素位置だけで決めて時間では動かさないので、グレインのようにちらつくこともありません。

## 画面サイズへの追従

`PerspectiveCamera` の `fov` は垂直方向なので、画面が縦長になるほど水平画角が削れて
被写体が左右にはみ出します。`stage.ts` の `fitScale()` が 16:9 との比からカメラの
引きしろを返し、`main.ts` がシーンのカメラ位置をその分だけ後ろへずらします
（引きすぎを避けるため 3 倍で頭打ち）。引いた分は霧が濃くなるので、`FogExp2` の
density も同じ比率で薄めています。

`devicePixelRatio` はウィンドウを別解像度のディスプレイへ移すと変わるため、
`resize()` で毎回 `setPixelRatio()` を入れ直し、さらに resize イベントを伴わない
変化に備えて `matchMedia('(resolution: Ndppx)')` の change も監視しています。

時間は `THREE.Timer` を `document` に繋いで回しているので、タブを離れている間は
`t` が進みません。1 フレームの `dt` にも 0.05 秒の上限を掛けてあり、重いフレームの
あとでアニメーションが飛びません。

## ホーム画面に追加する（PWA）

公開 URL をスマートフォンで開き、ブラウザの「ホーム画面に追加」を選ぶと、
アドレスバーのない全画面で起動します。一度開いておけば、機内モードなど
オフラインでもそのまま眺められます。

- `public/manifest.webmanifest` — 名前・アイコン・起動時の表示モード。
  `start_url` と `scope` を `"./"` にしてあるので、どのパスに置いても動きます。
- `public/sw.js` — Service Worker。ビルド成果物が index.html とハッシュ付きの JS
  だけなので、ファイル一覧を埋め込まず、install 時に HTML を読んで参照先の JS を
  取りに行く方式にしています。HTML は network-first なので、新しいビルドを出せば
  リロード 1 回で入れ替わります。
- `src/pwa.ts` — 登録。開発サーバでキャッシュが邪魔にならないよう、本番だけ登録します。

アイコンは画像ファイルを直接置かず、`src/palette.ts` と同じ配色で生成しています。
色を変えたら作り直してください。

```sh
npm run icons      # public/icons/*.png を再生成
```
