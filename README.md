# my-oddly-satisfying-animation

公開 URL: <https://siwasu17.github.io/my-oddly-satisfying-animation/>（`main` への push で自動デプロイ）

Three.js でつくった「見ていて気持ちのいい」ループアニメーション集。
いくつものシーンを自動／手動で切り替えながら眺められます。

就寝前に眺めることを想定して、色と明るさは全体に落としてあります（後述）。

## 起動

```sh
npm install
npm run dev      # http://localhost:5173/
```

その他のコマンド:

```sh
npm run build      # 型チェック + dist/ へ静的ビルド
npm run preview    # ビルド結果を確認
npm run typecheck  # 型チェックのみ
```

`vite.config.ts` で `base: './'` にしてあるので、`dist/` はどのパスに置いても動きます。

## 操作

| 操作 | 内容 |
| --- | --- |
| `1` – `9` / 画面上部のタブ | シーンを直接選ぶ（10 以降はタブか `←` `→` で） |
| `←` `→` | 前後のシーンへ |
| `Space` | 自動切替（34 秒間隔）の ON / OFF |
| `S` / 右下の「♪ 効果音」ボタン | 効果音の ON / OFF（既定は OFF） |
| ドラッグ / ホイール | 視点の回転・ズーム（放置するとゆっくり自動回転） |

URL の `#2` のようなハッシュで開始シーンを指定できます。切り替えるとハッシュも追従するので、
気に入った状態のリンクをそのまま共有できます。

## シーン

シーンは `src/scenes/` に 1 ファイル 1 本で置いてあり、`src/scenes/index.ts` が
そのディレクトリを丸ごと読み込みます。何をしているかは各ファイル冒頭のコメントと、
アプリのタイトル下に出る 1 行説明（`SceneModule.desc`）に書いてあります。

一覧は起動して画面上部のタブを見るのがいちばん早いです。

## シーンを足す（並列作業）

シーンは 1 ファイルで完結するので、複数の Claude Code セッションで並列に増やせます。
1 セッションが触るのは `src/scenes/<name>.ts` の 1 つだけで、レジストリも README も
書き換える必要がありません（`src/scenes/index.ts` がディレクトリを自動で読み込みます）。

```sh
npm run wt new koi-pond          # .claude/worktrees/koi-pond に worktree と scene/koi-pond ブランチ
cd .claude/worktrees/koi-pond
npm run new-scene koi-pond       # src/scenes/koiPond.ts ができる
npm run dev                      # ポートは自動採番。タブの末尾に出る
```

検証と引き渡し:

```sh
npm run typecheck
npm run build
npm run smoke koiPond            # dev サーバーを立てて配信を確認し、必ず落とす
npm run play -- --bg koi-pond    # 背面で起動して URL を出す（--stop で停止）
```

`main` への取り込みは親リポジトリで 1 コマンド。停止 → マージ → 衝突解決 → 検証 →
worktree とブランチの削除までを行います（手で `git merge` しないでください）。

```sh
npm run merge-scene koi-pond
npm run merge-scene koi-pond -- --dry-run   # 何をするか見るだけ
npm run merge-scene -- --list               # マージできる scene/* ブランチの一覧
```

Claude Code から `/new-scene` を使うと、worktree の用意から仕様決め・実装・検証・
コミットまで通しで行います。作業ルールの詳細は [`CLAUDE.md`](./CLAUDE.md) を参照してください。

## 水面の作り

Koi Pond の水面だけは、形を CPU で作らず「ある点の高さと傾きを返す 1 つの式」を
シェーダへ差し込んでいます。同じ式を

- 水面 … 頂点をその高さへ持ち上げ、**画素ごとに**傾きから法線を作る
- 水底 … その式の 2 階微分から集光模様を描く
- 浮き葉 … 葉の頂点をその高さに乗せる

の 3 つが共有するので、波・波紋・集光・葉の揺れは決してずれません。法線を頂点では
なく画素で作っているため、細かいさざ波は板の分割数に縛られずに残ります。

式そのものは正弦波を 8 本足しただけですが、速さは指定していません。深い水の波は
波長が長いほど速く進む（ω=√(gk)）ので、波長から角速度を計算しています。大きな
うねりはゆっくり、細かい波は速く走るというだけで、水面の動きは一気に水らしく
なります。

見た目は 3 つでできています。

| 要素 | 中身 |
| --- | --- |
| 屈折 | ガラスと同じ透過（`transmission`）材で、屈折率は水の 1.333。鯉が水越しにゆがむ |
| 映り込み | 岸の灯り 3 つと暖色の勾配だけの「夜空」を式で書き、フレネルの強さで足す。さざ波が向きを変えるたびに灯りが砕けて粒になる |
| 集光 | 屈折した光が底へ届くまでの面積の変わりぶん（ヤコビアン）の逆数。潰れて 0 に近づくところだけが細い筋になって光る |

鯉は体を直接動かすのではなく、**頭がたどってきた道を体長ぶんさかのぼって**背骨に
しています。時間で等分すると速さのむらで体が伸び縮みするので、距離を積みながら
拾い直しています。胴の断面は途中から横幅を潰しつつ高さを広げるだけで、そのまま
尾びれに化けるので、体と尾のつなぎ目が割れません。

## 効果音

各シーンには、その動きに合わせた効果音が付いています。右下のボタンか `S` キーで
ON / OFF でき、選んだ状態は `localStorage` に残ります。ブラウザは操作なしに音を
出せないので、ON で終了した場合も次に開いたときの最初のクリック／キー入力まで
待ってから鳴り始めます。

音声ファイルは持たず、`src/audio.ts` が Web Audio API の発振器とノイズだけで
組み立てています。用意しているのは 4 種類だけです。

| 音 | 中身 | 使いどころ |
| --- | --- | --- |
| `pluck()` | 正弦波 + 薄い倍音を指数減衰 | 珠・ドミノ・板が当たる音 |
| `drop()` | 音程を滑らせた短い正弦波 | 雨だれ、泡が水面へ抜ける音 |
| `air()` | 帯域を絞ったノイズ | 風、衣ずれ、輪が通り過ぎる音、群れの羽音 |
| `drone()` | わずかに離調した 2 本の持続音 | 呼吸・水底・回廊の低い響き |

入眠前に聴く前提なので、音程はペンタトニック（`tone()`）だけを使ってどう重なっても
濁らないようにし、出力全体を 2.4kHz のローパスと長い残響に通して「遠くで鳴っている」
状態に寄せています。音量も低めに固定しています。

鳴らすタイミングは、映像と同じ時刻 `t` から逆算しています。たとえばドミノなら
「`t / CYCLE - u` が整数をまたいだ瞬間 = その牌が倒れ始めた瞬間」です。この
「またいだ回数」を数えるのが `ticker()` で、音が OFF の間 `sound()` は呼ばれないため、
再開時にまとめて鳴らないよう最大 2 回で頭打ちにしています。

シーンが密なもの（ドミノ 84 枚、珠のれん 32 本など）は数本おきにしか鳴らしていません。
全部鳴らすと音が団子になり、眠るどころではなくなるためです。

## 色づくり

入眠前に眺める前提なので、青い光をほぼ使っていません。色は `src/palette.ts` の
`ember()` に集約してあり、色相は「くすんだ薔薇 → 赤 → 琥珀」の帯だけを使い、
明るいところほど彩度を落として白熱電球のような色に寄せています。シーン側は
0〜1 の値を渡すだけなので、パレットを差し替えれば全シーンの色味が一度に変わります。

トーンマッピングの露出は 0.92、ブルームは強さを落として半径を広げ（0.42 / 0.85 / 0.28）、
輪郭がじわりとにじむ程度に留めています。光源もろうそくに近い色温度で揃え、
UI の文字色やタブも同じ暖色にしてあります。

## 画面サイズへの追従

`PerspectiveCamera` の `fov` は垂直方向なので、画面が縦長になるほど水平画角が削れて
被写体が左右にはみ出します。`stage.ts` の `fitScale()` が 16:9 との比からカメラの
引きしろを返し、`main.ts` がシーンのカメラ位置をその分だけ後ろへずらします
（引きすぎを避けるため 3 倍で頭打ち）。引いた分は霧が濃くなるので、`FogExp2` の
density も同じ比率で薄めています。

`devicePixelRatio` はウィンドウを別解像度のディスプレイへ移すと変わるため、
`resize()` で毎回 `setPixelRatio()` を入れ直し、さらに resize イベントを伴わない
変化に備えて `matchMedia('(resolution: Ndppx)')` の change も監視しています。

## ホーム画面に追加する（PWA）

公開 URL をスマートフォンで開き、ブラウザの「ホーム画面に追加」を選ぶと、
アドレスバーのない全画面で起動します。一度開いておけば、機内モードなど
オフラインでもそのまま眺められます。

- `public/manifest.webmanifest` — 名前・アイコン・起動時の表示モード。
  `start_url` と `scope` を `"./"` にしてあるので、どのパスに置いても動きます。
- `public/sw.js` — Service Worker。ビルド成果物が index.html とハッシュ付きの JS
  だけなので、ファイル一覧を埋め込まず、install 時に HTML を読んで参照先の JS を
  取りに行く方式にしています。HTML は network-first なので、新しいビルドを出せば
  リロード 1 回で入れ替わります。
- `src/pwa.ts` — 登録。開発サーバでキャッシュが邪魔にならないよう、本番だけ登録します。

アイコンは画像ファイルを直接置かず、`src/palette.ts` と同じ配色で生成しています。
色を変えたら作り直してください。

```sh
npm run icons      # public/icons/*.png を再生成
```

## 構成

```
src/
├── main.ts            シーン切替・カメラ補間・メインループ
├── stage.ts           レンダラ / カメラ / ライト / ブルームの共通設定
├── palette.ts         全シーン共通の暖色パレット
├── audio.ts           Web Audio API による効果音（音声ファイルは持たない）
├── ui.ts              タブ・タイトル・キーボード操作
├── pwa.ts             Service Worker の登録（オフライン対応）
├── types.ts           SceneModule インターフェース
└── scenes/            シーン本体（1 ファイル 1 シーン）
    └── index.ts       シーンの自動収集と並び順

templates/scene.ts     新規シーンの雛形
scripts/               new-scene.mjs / wt.sh / dev-smoke.sh / play.mjs / merge-scene.mjs
```

シーンを足すときは `src/scenes/` に `SceneModule` を 1 つ export するファイルを置くだけです。
`src/scenes/index.ts` が同じ階層の `.ts` を自動で読み込むので、登録作業はありません
（並びは `index.ts` の `ORDER` 順で、そこに無いものはファイル名順で末尾に付きます）。
`build(root)` で追加したものは切替時に `disposeGroup()` がまとめて破棄するので、後始末は不要です。

効果音を付けるなら、任意の `sound(t, dt, sfx)` を足します。音が ON のときだけ
呼ばれるので、ここに映像へ影響する処理は書かないでください。`ticker()` を使う
場合は、シーンを開き直すたびに位相が 0 へ戻るよう `build()` で作り直します。
